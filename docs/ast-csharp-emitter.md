# Bound C# emitter

## Array parameter syntax (migration prerequisite)

AST array locals and Static storage now use a uniform `System.Array` carrier while retaining semantic element/rank metadata. Fixed arrays carry their actual CLR lower bounds, including negative one-dimensional bounds; indexing and LBound/UBound read the runtime storage rather than declaration offsets/constants. Sharing through Variant and assigning a matching typed array from Variant preserve identity and physical bounds. Typed Variant conversions check exact element type and rank before replacing old storage. Dynamic ReDim retains its existing rank-changing contract. String creation/ReDim/Erase preserve empty-string defaults across ranks and lower bounds. Ordinary, GoTo-hoisted and protected emission share allocation; hoisting does not skip allocation when the declaration is reached. CLI/MCP and Language/Runtime FullTest exercise `array-storage-bounds.xps`; `array-storage-parity.xps` supplies narrow normal/AST bounds and String Erase parity. Whole-array constructor signatures remain guarded below.

Declaration parsing retains the array rank and source tokens in `values() As Long` and `values(,) As Long`, including Optional/default metadata. Ranks one through eight are recognized; higher ranks and combined array/List declarations are syntax errors. Whole-array constructor, procedure and class-method parameters now use the shared `System.Array` carrier, preserving physical bounds and ByRef mutation through the existing typed reference helpers. Omitted Optional array arguments lower to unallocated `Nothing`/null array storage. CLI/MCP and Language FullTest cover bounded procedure/constructor/method execution, Optional omission, and invalid-rank/array-List guards.

Native byte-vector inputs reuse ByteVector: ordinary zero-based byte[] values pass through unchanged; bounded rank-one Byte arrays are normalized in element order only at the native boundary. The source array keeps its storage/bounds. Higher ranks and non-Byte elements are rejected. `image-array-byte-interop.xps` verifies actual image decoding, typed Byte reads and source-bound preservation in the shared image harness and permanent Runtime FullTest.

## Typed List constructor parameters

Constructors accept `ByVal values List As T` and explicit/implicit ByRef, including trailing Optional parameters. The shared parameter-type resolver carries the List shape and canonical element type through symbols, signatures, Parent.New scopes, body helpers and Optional carriers. ByVal shares the List object but replacing its parameter is local; ByRef replaces the caller's actual slot, preserving duplicate aliases and writes when construction fails. Different List element types remain invariant, including user-class ancestors; overloads retain semantic element types even when their C# representations coincide.

Omitted List parameters without an initializer start as Nothing, not an empty List. Each omitted ByRef gets a fresh StrongBox<LSList<T>> cell. Factories returning Variant are converted through existing typed List casts; defaults run once in order and may refer to earlier List parameters. Default failures preserve old targets and prior mutations. This does not alter ordinary List procedure element-copy-back wrappers or enable List signatures on ordinary class methods/accessors.

Lists borrow their elements, including XPImage references. Passing/replacing a List does not clone, Dispose, Delete or recycle its elements. Typed image field stores still clone and failed construction/Delete cleans those owned snapshots only. Declared scalar XPImage and array parameter signatures remain separate work, as do compatibility module addresses and broader lifecycle migration.

`class-constructor-list.xps` covers aliases, snapshots, defaults, errors, Parent.New, overloads and user/native element types. `image-constructor-list.xps` covers borrowed images and owned field cleanup. CLI/MCP pair invariant type/default/name/unknown-type errors and retain the ordinary method guard. Language/Runtime FullTest require AST_LIST_CONSTRUCTORS_OK and AST_IMAGE_LIST_CONSTRUCTORS_OK. `constructor-reference-list.xps` provides narrow normal/AST ByVal mutation parity; advanced replacement/ByRef/Optional behavior is AST capability (normal currently rejects ByVal `Set values = Nothing`).

## Variant and shared native constructor references

Constructor parameters support Variant and the existing JSON/XML/CSV/spreadsheet/HTTP native reference types, including required or trailing Optional ByVal/ByRef parameters. Binding, conversions, semantic signatures, native runtime selection and Optional forwarding reuse the shared compiler paths. Distinct semantic native types remain distinct overloads even when their C# representation is identical (XPHttpPart/XPHttpFile).

ByVal snapshots the value/reference; native object mutations remain shared. ByRef requires exact-type writable storage and replaces the caller's slot directly, preserving duplicate aliases and writes on failure. A native Optional reference without an initializer is Nothing; a Variant without an initializer is Empty. Omitted ByRef values use fresh StrongBox<T> cells, and later defaults see earlier cells. Explicit Nothing-to-Variant defaults retain the shared conversion rejection rather than introducing a constructor-specific conversion.

Shared native references and Variant-held images are borrowed: construction failure or Delete cleans only the new instance's owned typed image fields, never the input reference. Scalar XPImage constructor parameters now use the existing image-scope cloning/borrowing contract; HTTP clients still require explicit Dispose. Compatibility module addresses retain their existing storage guards. XPImage-declared procedure/method parameters retain XPS3001 until their lifetime contract is implemented; unknown types remain deferred. Ordinary class-method object signatures are not enabled.

See `class-constructor-variant.xps`, `class-constructor-native.xps`, `constructor-reference-variant.xps` and `image-constructor-variant.xps`. CLI/MCP pair exact ByRef/default errors; Language FullTest requires AST_VARIANT_CONSTRUCTORS_OK and AST_NATIVE_CONSTRUCTORS_OK, and Runtime FullTest requires AST_IMAGE_VARIANT_CONSTRUCTORS_OK. Narrow ByVal Variant legacy behavior is checked separately from AST ByRef/omission capability.

## Constructor overload selection

User classes can declare multiple Sub New signatures. Binding selects accessible signatures by supplied arity, implicit conversions and exact-type writable ByRef storage. Identity conversions and more specific reference types win; otherwise equivalent candidates prefer fewer omitted parameters. An unresolved tie reports XPS2005, no matching signature XPS2004, and duplicate signatures (types and ByRef modes, independent of parameter names/defaults) XPS2006. Optional forwarding and Parent.New retain selected constructor metadata. Generated per-signature tags prevent C# from selecting another overload or colliding with shortened Optional signatures. See `class-constructor-overloads.xps` and paired CLI/MCP diagnostics. XPImage/array parameter signatures remain separate work.

## Root-class constructors

### Optional ByRef references and typed reference storage

Object/user-class parameters support explicit or implicit Optional ByRef. Each omitted reference receives a fresh `StrongBox<T>.Value` cell, preserving the concrete semantic type through shared OptionalCallLowering and the stack-only argument carrier. Interior managed references keep cells alive across forwarding frames; no stack reference escapes, object-array type erasure, pointer casts or copy-back is used. Defaults start as Nothing unless explicitly initialized, run once in order and may share/read/mutate earlier references. Supplied exact-type storage remains live through default/body errors, nested New, Parent.New and implicit bases. ByVal snapshots remain independent slots.

User-class array/List element types are preserved in binding and all ordinary, flat/error-flow, Static and alias emission paths. Required/Optional constructor references accept exact typed fixed/dynamic/multidimensional array elements, including lower bounds, List entries and writable List ForAll aliases. Typed initializer-free Object/user-class module variables also provide real storage. Incompatible elements remain XPS2003; accessor results and initialized compatibility module storage remain deferred. Ordinary List procedure wrappers keep their existing separate contract; array ForAll does not gain List alias semantics.

References do not acquire ownership of user objects or their image fields. Failed construction preserves old results and supplied reference writes while clearing only the new instance's owned image fields. Default factory image locals retain normal cleanup. See `class-constructor-optional-refref.xps`, `class-constructor-reference-storage.xps` and `image-constructor-optional-refref.xps`. CLI/MCP and permanent Language/Runtime FullTest cover these cases, including exact element type rejection. Scalar XPImage and array parameter signatures remain subsequent work.

### Optional ByVal Object and user-class constructor parameters

Trailing `Optional ByVal value As Object` or `As Box` parameters are supported by New, Parent.New and implicit all-Optional bases. An absent initializer means Nothing, not a newly allocated Object. Explicit Nothing, fresh New expressions, user-class upcasts and dependent defaults use the existing conversion rules. Defaults execute once, sequentially after supplied arguments, with only earlier parameters and module declarations in scope. Full-arity calls skip defaults.

Reuse shared OptionalCallLowering and semantic local/carrier types for both value-only and stack-only mixed ByRef carriers. Omitted ByVal references are fresh snapshot slots; mutations affect the shared object, but clearing the parameter does not clear its caller. Required ByRef writes survive default failures while an old construction target is preserved. Optional ByRef references use the typed cells described above. XPImage/array signatures remain deferred.

Default-created user objects are not recursively owned. Their typed image fields survive constructor failure and Delete of the new instance; retain their owners for explicit Delete. Factory image locals retain ordinary cleanup, while the constructed instance's own image snapshots are cleared on failure. `class-constructor-optional-reference.xps`, `constructor-reference-optional.xps` and `image-constructor-optional-reference.xps` cover these contracts. Paired CLI/MCP regressions validate incompatible defaults and earlier-only name scope. Permanent Language/Runtime FullTest require AST_OPTIONAL_REFERENCE_CONSTRUCTORS_OK / AST_IMAGE_OPTIONAL_REFERENCE_CONSTRUCTORS_OK. Normal omitted-constructor parity is not claimed.

The CLI, constructor and image harnesses accept `XPSCRIPT_TEST_OUTPUT_ROOT` to place generated outputs outside the default repository `out` directory. Existing defaults are unchanged.

### Required ByRef Object and user-class constructor parameters

Root and derived constructors accept required `ByRef value As Object` or a concrete user class, including unmodified/default ByRef. Supply exactly typed writable locals, constructor parameters or real user-class fields (qualified/With fields included). A typed variable whose current value is Nothing is valid; a temporary, accessor result or Variant is not an address of that declared type. ByRef is identity-only: neither subclass-to-base conversion nor a concrete-class slot passed as Object is allowed (XPS2003). New/temporary values fail XPS2001 and accessor-backed storage XPS3001. Typed initializer-free reference module variables, matching array/List entries and writable List ForAll aliases are supported through the typed storage described above.

Reuse the shared address validator, FunctionSymbol passing modes and direct managed-reference argument emitter. No copy-back or pointer casts are added. Duplicate locations stay aliases through replacement and clearing; each field receiver is evaluated once in argument order, and changes made by later arguments/defaults are visible immediately. Required reference arguments can precede scalar Optional ByVal/ByRef parameters through the existing stack-only typed carrier. Parent.New and nested New forward the same reference slot; passing a child's ByVal reference parameter to a ByRef base changes only that child's snapshot.

Reference replacement survives default/argument/base/body errors even when the new object's assignment target is preserved. Replacement is not ownership transfer: it does not Delete the old argument object or consume either argument object's images. Retain an old image-owning object if explicit cleanup is needed. Only the new instance's typed image fields and ordinary local/default image scopes are cleaned on failure, without user Delete. Stored user-class/Object fields hold reference values, not permanent aliases to the parameter slot. Declared XPImage/array parameter signatures remain deferred; ordinary method signatures are unchanged.

`class-constructor-reference-byref.xps` covers duplicate/live aliases, fields/receiver order/With, exact typed Nothing slots, implicit modes, both passing modes through Parent.New, nested constructor forwarding, scalar Optional defaults and exceptional writes. `image-constructor-reference-byref.xps` covers Object replacement during defaults/base arguments, concrete-class replacement in a throwing body, retained old targets and borrowed versus owned images. CLI/MCP pair type/address/ancestor errors and retained storage/signature deferrals. Language/Runtime FullTest require AST_BYREF_REFERENCE_CONSTRUCTORS_OK / AST_IMAGE_BYREF_REFERENCE_CONSTRUCTORS_OK. `constructor-reference-byref-simple.xps` prints 7 through AST, but normal compilation currently prints 0: this is AST capability, not claimed ByRef legacy parity. Existing valid ByVal parity remains separate. Module functions' concrete-class signature migration is not enabled by constructor support; the image helper uses existing Object/Variant binding.

### Required ByVal Object and user-class constructor parameters

Root and derived constructors accept required `ByVal value As Object` and required concrete user-class parameters such as `ByVal value As Box`. These are shared reference snapshots: object mutations are visible through aliases, while replacing/clearing the parameter cannot replace the caller's variable or a child's ByVal parameter. New and Parent.New use the existing compilation-local ancestry/conversion rules, including Nothing, user-class upcasts and existing Variant conversions. Statically scalar Object arguments, unrelated classes and implicit downcasts fail with mapped XPS2004; no second constructor binder or reference-conversion policy is added.

Preserve canonical semantic types through constructor signatures, body helpers, scalar Optional forwarding signatures and carrier fields. Required reference parameters may precede Optional scalar ByVal/ByRef parameters; defaults can read earlier reference members and module routines can share mutations. Supplied expressions run once in order before defaults. Ordinary class-method object parameters remain deferred: only constructor bodies bypass their scalar-signature guard. Declared XPImage/array parameter signatures, unknown types remain explicit XPS3001 deferrals.

Constructor reference parameters do not acquire ownership. A user object containing images stays borrowed: failed construction clears only the new object's completed typed image fields, not the argument object's fields or user references. Default/body image locals retain existing scopes, no user Delete runs on failure, and an old assignment target survives. Successful instances still need explicit image-field cleanup/Delete; no GC finalizers or recursive ownership are introduced. Opaque Object/Variant aliases do not become owning XPImage parameters.

`class-constructor-reference.xps` verifies identity, snapshot replacement, user-class typing/upcasts, Nothing/Variant conversions, argument order, typed earlier-member defaults, both Optional carrier paths, caller-default rewriting, Parent.New and shared mutations on errors. `image-constructor-reference.xps` verifies borrowed input survival versus owned image snapshots/local cleanup in default/base/derived failures and explicit Delete. CLI/MCP pair incompatible arguments and all retained signature/method deferrals. Language/Runtime FullTest require AST_REFERENCE_CONSTRUCTORS_OK and AST_IMAGE_REFERENCE_CONSTRUCTORS_OK. `class-constructor-reference-parity.xps` compares concrete-class input mutation/snapshot behavior with normal compilation; broader Object/default/error cases are AST capability coverage, not a claim of complete legacy parity.

### Optional ByRef constructor parameters

Root and derived constructors accept trailing scalar `Optional ByRef` parameters, including implicit ByRef (`Optional value As Long = 1`). Omit only a trailing suffix. Each omitted parameter gets fresh storage per call; later defaults can read or mutate earlier omitted references. Supplied arguments require the same exact-type writable storage as required ByRef parameters and remain live aliases, including duplicate locations. Full-arity calls never evaluate defaults. All-Optional base constructors may be invoked implicitly; Parent.New forwards both supplied and omitted references. Defaults still see only earlier parameters/module declarations, not the instance or body locals.

Constructor forwarding opts into heap-backed ByRef defaults in the shared OptionalCallLowering. Each omitted reference uses a fresh one-element typed array. A scalar temporary establishes the declared type before boxed array assignment (including Byte zero defaults). Default substitutions and calls use that array slot, not a copied scalar; the existing typed managed-array reference emitter carries it through the private ref-struct argument carrier and C# initializer chain. Interior managed references keep the array alive without leaking a stack reference, boxing the carrier, pointers, or copy-back. Ordinary procedure/accessor Optional lowering keeps its existing stack-local behavior. ByVal-only constructor carriers are unchanged.

Writes to supplied locations survive default/base/body errors. Failed construction preserves the old target and cleans completed image fields without user Delete; image-owning default routines retain their usual local scopes. `constructor-optional-byref-zero.xps` runs early to guard Byte boxing and fresh scalar zero storage. `class-constructor-optional-byref.xps` covers dependent/mutating defaults, explicit/implicit modes, mixed arities, generated-name collisions, arrays/Lists/ForAll, Optional caller rewriting and base forwarding. `image-constructor-optional-byref.xps` covers image-owning defaults, child/base default failures, body failures and cleanup. CLI/MCP pair literal/type/default-name/default-type/Parent.New diagnostics. Language/Runtime FullTest require AST_OPTIONAL_BYREF_CONSTRUCTORS_OK and AST_IMAGE_OPTIONAL_BYREF_CONSTRUCTORS_OK. XPImage parameter signatures and List/array parameters remain deferred; legacy ByRef/omission parity is not claimed.

### Required scalar ByRef constructor parameters

Root and derived constructors accept required scalar ByRef parameters, including the language's unmodified/default ByRef mode. Constructor FunctionSymbol metadata carries the modes through BoundNewExpression and Optional caller rewriting. New, real base initializers and the private body helper use direct managed references; there is no constructor copy-back wrapper. ByVal parameters remain snapshots, including a child's ByVal parameter passed by reference to a base constructor: base writes affect that child's local parameter, not the original caller.

Constructors share indexed-accessor scalar reference validation and argument emission. Arguments must have exactly the declared scalar type and writable storage: locals/parameters, user-class fields, initializer-free typed Private/Public module scalars, typed array/List elements and typed List ForAll aliases. Each receiver/index/tag is evaluated once in argument order. Duplicate locations share one live reference; writes made while evaluating later arguments remain visible. Array bounds and missing List tags fail before later arguments/body execution; existing reference helpers retain multidimensional/lower-bound checks and detached List-cell behavior. Accessor results are not writable references (XPS3001), scalar temporaries are invalid (XPS2001), type mismatches are XPS2003 and unsupported module storage is XPS3001. CLI/MCP pair these diagnostics for New and Parent.New.

Reference writes survive constructor/base/argument errors while a failed replacement preserves the old target. Existing image scopes and non-virtual field cleanup still run without invoking user Delete. `class-constructor-byref.xps` covers duplicate aliases, fields/receiver order, typed module storage, arrays/Lists/ForAll, String slots, protected bodies, parameter forwarding and Optional caller rewriting. `image-constructor-byref.xps` verifies reference updates and local/inherited field cleanup on base/derived/argument failures. Language/Runtime FullTest require AST_BYREF_CONSTRUCTORS_OK and AST_IMAGE_BYREF_CONSTRUCTORS_OK. `class-constructor-byref-simple.xps` is AST capability coverage: normal compilation builds its classic-declaration form but execution currently fails with `'long' does not contain a definition for 'Value'`. Existing valid ByVal normal/AST parity remains; ByRef parity is not claimed.

Required ByRef parameters can precede trailing Optional ByVal parameters. Optional ByRef parameters are supported with fresh heap-backed omitted storage. XPImage parameter signatures and List/array parameters remain deferred. This does not enable ordinary derived method/accessor bodies, GC finalizers or LSRef alias invalidation.

### Optional ByVal constructor parameters

Root and derived constructors accept a trailing Optional suffix of explicitly ByVal scalar parameters. ### Derived constructors and Parent.New

Derived classes also execute one `Sub New(...)` with the same required scalar ByRef/ByVal signature contract, including a trailing Optional suffix. Put `Call Parent.New(...)` first to initialize the direct base; it is lowered to a real C# base initializer, not a procedure call in the body. Without forwarding, an accessible zero-argument base call is required (including an all-Optional signature). Arguments use shared binding/conversions and run once, left to right before base bodies; parameter/module names are available, but Me, fields and body locals are not. Invalid position (including nesting/duplicates/root use) produces mapped XPS1012; missing/incompatible base arguments XPS2004, private base construction XPS2009 and unknown argument names XPS2008. These diagnostics are paired in CLI/MCP.

Constructor bodies use the existing validated lineage scopes and shared BindProcedure/BoundMethodEmitter, including private own fields, inherited public helpers/fields, Me/With, Exit Sub and On Error. Base-private members and ordinary derived method/accessor bodies remain unavailable. Failed construction uses a separate non-virtual wrapper chain calling the existing AstImageScope.StoreField helper: clear own fields, then completed ancestors in finally, never user Delete. A failing base cleans its completed ancestry before the child body can run. A scalar base-argument failure does not enter that base. Existing assignment targets survive. No finalizer/GC or Variant ownership is introduced.

`class-constructor-derived.xps` covers three levels, casing, ByVal snapshots, argument order/conversion, private shadowing, inherited ByRef helpers and protected bodies. `class-constructor-derived-parity.xps` matches real normal execution. `image-constructor-derived.xps` verifies successful field survival, failures at every level and during base argument evaluation, local/inherited field cleanup and explicit later Delete. FullTest requires AST_DERIVED_CONSTRUCTORS_OK and AST_IMAGE_DERIVED_CONSTRUCTORS_OK in the existing Language/Runtime harnesses. Overloads, XPImage/array constructor signatures remain mapped XPS3001; full lifecycle migration remains open.

AST executes declared `Sub New(...)` overloads in a root class, with required or trailing Optional scalar ByRef/ByVal parameters (or no parameters). Constructor metadata is registered before body binding; New resolves case-insensitively to the declared class spelling, including through Optional call rewriting. Arguments run once, left to right, using the shared implicit-conversion rules. Missing/incompatible arguments produce mapped XPS2004, external private construction XPS2009 and body errors their usual mapped diagnostics. Plain `Dim item As ClassName` starts as Nothing; only New constructs an instance.

Constructor bodies reuse BindProcedure and the instance BoundMethodEmitter in a private helper, including Me, private helpers, Exit Sub and On Error. Successful construction retains typed image fields while cleaning body locals. Failed construction clears its own typed image fields through AstImageScope.StoreField and propagates the error without calling user Delete; a failed replacement leaves the caller's old reference unchanged. Variant observation aliases do not establish ownership or imply GC cleanup.

Derived classes without a declared constructor implicitly call an accessible parameterless base constructor. XPImage/array parameters remain mapped XPS3001 deferrals. Full lifecycle migration remains open. `run-ast-constructor.ps1` runs first in the CLI suite, with real normal/AST parity kept separate from extended AST capability tests; MCP checks the same successes and diagnostic codes/lines. ## Instance class-method increment
