# Bound C# emitter

## Instance class-method increment

Typed HTTP Get/Set supports the seven client/request/response/part/file/collection reference types through AstHttpSupport's existing mappings and the shared property binder/emitter. References are shared, incoming setter values are snapshots, reference results begin as Nothing, and scalar Optional/ByRef indexes preserve aliases through errors. Clients keep explicit Dispose semantics; no accessor clones or automatically owns/disposes them. `http-reference-properties.xps` executes real local HTTP/TLS and multipart traffic, native member chains, source/reference identity, mutation, instance state, With, Nothing, error exits and shared disposal. The same fixture confirms private-network and Strict/self-signed/hostname/expiry enforcement through getters. `http-property-signature-only.xps` covers conditional runtime selection for all seven native getter types. Distinct XPHttpPart/XPHttpFile static names remain invariant; the fixture uses the existing Variant runtime cast for the file facade. CLI/MCP pair type/mode/native-read-only diagnostics and retain object-index and image-accessor deferrals. The normal compiler still rejects the fixture's Optional wrapper with XPS1012; this is not complete legacy parity. HTTP and Language FullTest reuse the existing probe/server rather than introducing a transport implementation.

Typed CSV/spreadsheet Get/Set also supports XPCsvDocument, XPCsvHeaderCollection, XPCsvRowCollection, XPCsvRow, XPCsvColumnCollection, XPCsvColumn, XPSpreadsheet, XPWorksheet, XPCell and XPRange. The existing semantic type mappings and accessor wrappers retain shared native references; no parser, spreadsheet engine, cloning policy or package is added. `tabular-reference-properties.xps` covers chained CSV/cell/range mutation, instance state, Nothing, With, Optional/ByRef indexes, incoming reference snapshots and exceptional exits. `tabular-reference-signatures.xps` covers typed getters/setters for every supported family. The existing FromBytes lowering still requires a writable document variable: read a property into a local, call FromBytes on that local, then Set the property to the replacement. Existing aliases retain the previous document. CLI/MCP pair incompatible-type, Set-mode, FromBytes-location and native read-only diagnostics, and retain image accessor deferrals. Normal compilation still rejects the runtime fixture's Optional wrapper with XPS1012; full legacy parity is not claimed.

Typed native Get/Set supports XPJsonDocument, XPJsonObject, XPJsonArray, XPJsonElement and the XPXml document/node/element/attribute/collection/validation reference types. Indexed accessors retain scalar Optional/ByRef indexes and snapshot the incoming reference; non-indexed parameterless Set is also supported. JSON/XML values share references, without image-style cloning or disposal. XML element-to-node value upcasts reuse the native conversion classifier. Generated script classes are assembly-local, permitting signatures that expose internal native runtime types without widening runtime visibility. Runtime selection still uses the existing registry, even for signature-only use. `native-reference-properties.xps` executes identity, mutation, Nothing, Optional indexes, setter snapshots and error exits; `native-reference-signatures.xps` covers every supported signature family. CLI/MCP pair success and mapped incompatible-type/assignment-mode/image-deferral diagnostics. Normal compilation still rejects these fixtures (Optional wrapper and native getter Set result), so this increment establishes AST capability, not legacy parity.

User-class reference values support implicit derived-to-base conversions, including transitive ancestry, in property assignments/results, initializers and supported ByVal calls. `SymbolTable.ClassifyConversion` reuses the existing conversion classifier and consults a compilation-local ancestry registry only when a declared scalar user-reference conversion is needed. Child scopes share their compilation's registry; separate compiler/MCP requests do not share hierarchy state. `ReferenceUpcast` emits a cast to the semantic base type and preserves identity, mutation and Nothing. Base names are resolved case-insensitively to their declared C# spelling. Before any inherited-member traversal, unknown bases produce mapped XPS2008 and direct/transitive inheritance cycles produce mapped XPS1012. ByRef storage remains invariant: an upcast is not an identity conversion, so a Leaf variable cannot alias a ByRef Root parameter. Arrays and Lists do not acquire covariance, and implicit base-to-derived or sibling conversions remain invalid. Variant casts retain their existing runtime behavior. This does not enable bodies declared in derived classes, constructor forwarding or complete lifecycle dispatch.

`inherited-reference-runtime.xps` covers three-level identity/mutation, field and initializer conversions, getter result construction, indexed/Optional setter snapshots, With, Nothing and exceptional exits. Early binder probes cover scope isolation, case-insensitive/transitive classification, ByVal/ByRef distinctions, array/List invariance and bounded malformed-registry traversal. CLI/MCP pairs cover downcasts, siblings, unrelated classes with reused names, cycles and unknown bases. Normal compilation still rejects the runtime fixture's Optional property wrapper with XPS1012; this remains AST capability coverage rather than full legacy parity.

Object and user-class properties now retain semantic reference types in symbols, fields, parameters, result slots and generated signatures. Both indexed and non-indexed Get/Set use the common accessor binder/emitter. A typed getter result supports direct member access such as `store.Item(1).Value`; an unassigned reference result and uninitialized reference field start as Nothing. Indexed Set parses as a call-shaped assignment target and is validated by the binder, so an ordinary Function call remains non-writable. User properties carry their declared assignment mode through member binding and Optional expression rewrites: Property Set requires `Set`, Property Let rejects `Set`, and statically scalar or incompatible concrete class values fail with mapped XPS2001 diagnostics. Supplied ByRef scalar indexes retain shared locations through getter/setter calls, RHS evaluation and exceptional exits; omitted Optional indexes retain fresh storage. The setter value is a snapshot reference even when its accessor parameter is ByRef; replacing that parameter does not replace the caller's source reference, while mutations to the shared object remain visible. Private/read-only/write-only permissions retain the existing binder checks. Typed JSON/XML/CSV/spreadsheet/HTTP reference accessors are supported; other native families (including XPImage ownership), derived accessor bodies and complete lifecycle dispatch remain deferred. `indexed-object-runtime.xps` and `samples/indexed-object-properties.xps` execute through AST and are validated through MCP. The existing sample still fails normal compilation on an LSRef<Script.Box> argument mismatch, so this is AST capability coverage.

Scalar indexed Get/Let supports an omitted trailing suffix of Optional indexes, including `store.Item()` when every index is Optional. `IndexedPropertySymbol.RequiredArgumentCount` validates arity; instance forwarding bodies reuse `OptionalCallLowering` and the ordinary bound method emitter. A setter's final incoming-value parameter remains required, even after Optional indexes. Getter/setter index counts, types, explicit ByRef modes and Optional positions must agree; each accessor evaluates its own declared defaults. Defaults bind in instance declaration scope with earlier indexes available, but not later indexes, accessor locals or the incoming setter value. Missing scalar defaults use zero/False/empty String. Defaults execute once, left to right at accessor entry, after supplied receiver/index arguments and (for Let) the RHS have been evaluated. Omitted ByRef indexes receive fresh local storage on every call; supplied ByRef locations retain direct aliases, including duplicate targets and exceptional exits. ByVal/unmodified supplied indexes remain snapshots. Internal, Me and With calls, write-only accessors and default-expression errors use the same path. Explicit empty argument slots and Optional ordinary class methods remain deferred. `indexed-optional-simple.xps`, `indexed-optional-runtime.xps` and mapped negative fixtures run first in AST CLI/MCP coverage; these are AST capability tests rather than a claim of full legacy parity.

Normal compilation of `indexed-optional-simple.xps` currently rejects the Optional declaration in its lowered property wrapper with XPS1012. The Optional-index fixtures therefore establish AST capability, not normal/AST parity.

The element-index fixtures are AST capability regressions: the smaller fixture compiles normally, but legacy execution still fails on numeric Value access. `list-stable-storage.xps` separately verifies real normal/AST parity for shared List assignment, ForAll alias mutation and Erase. `indexed-byref-list-lifetime.xps` verifies captured references during tag removal/recreation and dictionary growth; no copy-back recreates an erased cell.

Typed array/List elements and List ForAll aliases are writable ByRef indexes for Get/Let. Array references use the shared runtime's managed array storage with exact element-type, rank and bounds checks before obtaining a managed reference; no extra package is needed. List values use stable framework cells so assignment and dictionary growth do not invalidate an existing reference. Removing/recreating an entry detaches the old captured cell instead of resurrecting it through copy-back. The common indexed argument emitter evaluates receiver/subscripts/tags once in order and passes direct aliases, including duplicate targets. Existing ordinary List call copy-back wrappers retain their contract; this increment does not claim their shared-alias migration. Typed List alias storage and dynamic-array storage are preserved through ordinary, flat and error-flow emission. Fixed one-dimensional array sizes/index offsets use declared upper/lower bounds. `indexed-byref-elements-runtime.xps` and `indexed-byref-elements-simple.xps` cover these paths; the compiler probe executes the production reference helper's type/rank/bounds guards, scalar layouts, reference-valued slots and non-zero lower bounds for ranks 1–8.

Typed module storage currently covers Boolean, Byte, String, Integer/Long and Single/Double/Currency. Date and other module types remain on compatibility storage and are not indexed ByRef targets in this increment.

Scalar module variables declared with Private/Public and no initializer now use typed storage with zero/false/empty-string defaults. `AstModuleFieldSupport` shares one storage description between symbol registration and field emission, excluding class/procedure bodies. `VariableSymbol.HasTypedStorage` authorizes direct ByRef index aliases without a separate copy-back engine. `indexed-byref-module-runtime.xps` exercises numeric/String/Boolean/Byte storage, shared aliases, class-body access, forwarding, shadowing, RHS order and exceptional exits. Mismatched types and unmigrated storage have mapped CLI/MCP diagnostics; module headers are masked rather than removed so their length does not shift these diagnostics. Initialized/reference-type module storage remains on the compatibility path and is not accepted as an indexed ByRef target. The smaller `indexed-byref-module-simple.xps` executes successfully in AST but normal compilation still fails at runtime on numeric Value access; it is a capability regression, not full legacy parity.

Explicit ByRef scalar indexes preserve real aliases for named scalar locals, parameters, typed uninitialized module variables and user-class fields, including qualified member access and implicit With fields. Both accessor wrappers and call sites carry the mode; getters and setters must agree. The same field or variable may be passed to multiple indexes, and changes remain visible even when an accessor throws. `PropertySymbol` and bound member expressions retain field-storage provenance so accessor-backed/native properties are not mistakenly passed by reference. The shared index argument emitter uses direct references, without another copy-back engine. `indexed-byref-runtime.xps` exercises mixed modes, internal/qualified fields, shared aliases, forwarding, exceptional exits and setter/RHS order. Literal/non-writable arguments, accessor-backed properties, incompatible types and incompatible accessor modes have mapped CLI/MCP diagnostics. Initialized/other module storage and accessor-backed locations remain explicit deferrals. ByVal/unmodified index snapshots retain their earlier behavior.

The complete ByRef exception/Resume fixture is an AST capability regression: normal compilation currently fails on generated Resume/Goto label scope. The smaller `indexed-byref-field-capability.xps` compiles normally but fails at runtime because the legacy path accesses Value on a numeric field. AST executes its getter/setter aliases successfully. Existing ByVal getter parity remains tested separately; neither capability fixture claims full legacy parity.

Scalar indexed Get/Let accessors use the existing `IndexedPropertySymbol` and bound indexed expression. Typed index arguments and read/write permissions are validated in the shared binder. Generated method wrappers call bound accessor bodies; receiver, indexes and assigned value are evaluated once in that order. Multiple indexes, bare internal access and case-insensitive With calls are executable. Index inputs (ByVal or unmodified declarations) are snapshots; accessor-backed ByRef locations remain XPS3001 deferrals, as do other native-family accessors and derived accessor bodies. Normal/AST getter parity is covered by `indexed-get-parity.xps`; the existing indexed scalar sample and `indexed-properties-runtime.xps` cover Get/Let, instance state and On Error. Shared semantic storage typing preserves class locals in error-flow emission, avoiding object-typed backend member failures.

The existing `samples/indexed-properties.xps` is an AST capability regression, not a full legacy-parity claim: normal compilation currently succeeds but execution fails for its unmodified scalar-index declarations. Explicit ByVal getter inputs have real normal/AST execution parity. Do not remove the legacy-path limitation from documentation until its separate runtime regression is fixed.

Scalar, non-indexed user-class properties lower their Get/Let bodies through the shared procedure binder and instance method emitter. Getters use a result slot: assigning the property name does not exit the accessor. A parameterless `Property Let Name As String` reads its incoming value as `Name`; a declared setter parameter retains its name and mode. Generated properties delegate to these bound bodies instead of storing fabricated auto-property state. Private accessors and read-only/write-only restrictions are checked during binding, including implicit With members. Object/reference `Property Set` and matching object `Property Get` preserve `Nothing`, replacement and alias identity through the same bound accessor path. Regression coverage is `class-properties-native.xps`, `object-property-set.xps`, `indexed-object-runtime.xps` and mapped CLI/MCP negative fixtures.

`class-properties-native.xps` compares normal and AST execution using existing implicit incoming-value syntax. Explicit non-indexed setter parameters and mixed-case implicit With calls are tested separately in `class-properties-capability.xps`: normal compilation currently rejects the explicit-parameter setter form. Do not infer legacy parity for that AST capability.

AST emits scalar typed Sub/Function bodies in user classes through `AstClassMethodSupport`, the same procedure binder/label/loop validation used by module routines, and `BoundMethodEmitter` in instance mode. Supported coverage includes per-instance scalar fields, private sibling calls, Me, recursion, scalar ByRef, result assignment/fall-through and parameter shadowing. Private members are omitted from external lookup; class declarations are excluded from module-field scanning. Default String fields start empty. Existing parameterless construction and inherited-field behavior remain in place.

Bound member names are canonicalized case-insensitively. `class-method-case.xps` is AST-only because normal compilation currently rejects that casing. `class-methods-native.xps` compares real normal/AST execution; negative fixtures cover private access, foreign class fields and diagnostics inside method bodies. Language FullTest and MCP run these early.

This does not close full class migration. Object/array/List signatures, Optional parameters, Static method-local storage and bodies declared in derived classes are explicitly deferred with XPS3001. Other native-family property accessors, constructor arguments/base-constructor forwarding and user destructor dispatch remain separate TODO items. No additional parser, runtime engine or NuGet addon is introduced. Program helper imports are scoped to generated user classes, not runtime code.

AST output includes the full shared `XPScriptRuntimeSource` and `TypeCoercionRuntimeSource`. Conversion, printing, Null/Empty, type inspection, scalar/string helpers, environment lookup and loop ranges use the production runtime; the former nested scalar substitute is removed. `tests/ast-compile-probe/shared-runtime.xps` compares runtime output with normal compilation and is covered by CLI/MCP and permanent FullTest regressions. Extended UI/helper placeholders remain tracked separately.

Object locals without an initializer start as Nothing. `Dim value As Object` resets its reference on every procedure call, while `Static value As Object` retains assignments across calls. Both require explicit object creation, for example `Set value = New Object()`. `object-local-lifetime.xps` compares both declarations over repeated calls in Language FullTest.

Explicit `Dim value As Object = New Object()` creates an object each time the declaration executes. The experimental AST extension `Static value As Object = New Object()` executes once when control first reaches the declaration, and does not rerun on subsequent procedure calls, even after `Set value = Nothing`. `object-initializer-lifetime.xps` verifies this difference by clearing both references before calling the procedure again. Static initializers can read parameters and earlier locals from that first execution. A generated Boolean records successful initialization; it is set after the initializer completes. `static-initializer-scope.xps` verifies skipped declarations, first-call parameter/local values and one-time side effects. Recursive initializer calls and concurrent first execution remain outside this verified contract.

`ParameterSyntax` retains Optional tokens, default expressions and full source spans, including nested default-expression commas. Explicit empty call slots use `OmittedArgumentExpressionSyntax`, preserving position and a zero-width absolute span rather than inventing Null values or missing names. Experimental CLI calls can omit declared Optional parameters, including slots before supplied required parameters. Semantic binding validates supplied types/modes and required positions, then registers only forwarding shapes actually used. Named default evaluators occupy omitted argument positions, preserving left-to-right evaluation before later supplied arguments. Full-arity forwarding methods use writable ByVal parameters for omitted values and preserve supplied ByRef aliases and Function results. Defaults are bound and checked for type compatibility. Complete declaration/default-name validation, overload conflicts, source mapping and machine-interface parity remain pending; this does not complete Optional migration.

The executable CLI regression covers repeated calls, supplied ByRef alias mutation, explicit and implicit defaults, string defaults and temporary-name collisions; incompatible defaults are rejected before Roslyn. `tests/ast-compile-probe/optional-byref-compatibility.xps` now passes legacy and AST execution with fresh literal-default reference storage in both paths. The legacy fix also prevents nesting those compatibility wrappers in generic ByRef temporaries. The published main binary under `publish/xpscript/win-x64` (build 2026-10-08) still reproduces the original runtime failure; preserve that baseline distinction during migration verification. MCP validates the same fixture through production `CompilerDriver`, not `AstExperimentalCompiler`, so experimental Optional diagnostics are not exposed through MCP yet.

Unresolved member properties and method calls now fall back dynamically only for a Variant receiver. An object-backed declared user type retains its semantic identity and reports `XPS2009` at the unknown member span. The permanent binder regression covers both cases with dynamic member support enabled.

Declared overload sets now produce `XPS2004` when arity, argument type or ByRef mode does not match, even with dynamic member support enabled. The binder no longer invents an overload to defer those errors to Roslyn. Variant receiver member calls remain dynamic. The permanent binder probe covers both paths and preserves failing call spans; object-backed user types retain unknown-member diagnostics as described above.

Function results in the experimental CLI are now lowered structurally: a collision-free local stores assignments and reads of the function name, while recursive calls still bind to the procedure. `Exit Function` and fall-through return the stored value. The CLI regression covers accumulation after result assignment, an empty numeric function, recursion, and a source local colliding with the generated-name prefix. The old regex replacement of function-name assignments with `Return` has been removed.

The experimental CLI binds every parsed top-level Sub/Function in a separate child scope and emits actual bodies through `BoundCompilationUnitEmitter.EmitMembers`. Signatures retain declared ByRef modes; arbitrary shortened overloads and empty procedure stubs are no longer generated. The CLI regression verifies a forward Function call and a ByRef Sub mutation producing 43. Only omission shapes selected for declared Optional parameters produce forwarding signatures. Original source mapping and machine/MCP integration remain pending; runtime placeholders and unsupported-syntax handling still prevent claiming general AST compatibility.

`BoundCompilationUnitEmitter` now emits a console `Program` compilation unit from a list of `BoundMethodDefinition` signatures and bodies. It delegates each body to `BoundMethodEmitter`; it does not parse source, bind symbols, synthesize runtime helpers or select an entry point. `tests/ast-compile-probe` parses and binds two Subs, emits them together, and compiles and invokes Main with Roslyn. Production CLI/MCP integration, runtime support, fields, classes and target-specific units remain pending.

The emission regression also executes both `Not RunCommand(...)` and `RunCommand(...) = False` with the explicit bound String-array conversion and both possible command results. The Language FullTest runner executes the AST CLI fixture and lexer compatibility regression before the broader emission and compilation probes. The CLI fixture uses a Variant iterator for the untyped `Array(7, 8)` result; the typed-array emission fixture supplies its iterator declaration and runtime conversion helper explicitly.

Phase 8 begins with an experimental method-body emitter. It consumes bound nodes and does not parse XPscript text. Production CLI and machine compilation continue using their existing shared compiler path.

`BoundExpressionEmitter` emits literal CLR types explicitly, escapes C# strings with Roslyn, and preserves Null as `System.DBNull.Value`. Empty and Nothing retain their CLR null representation. It emits bound conversions, using existing `XPScriptRuntime` conversion functions for Variant to String, Long, Double and Boolean. Other Variant targets are rejected until their lowering is implemented.

`BoundStatementEmitter` supports ordinary assignment, calls, return, If/ElseIf/Else, For, ForAll, While, pre-test/post-test Do While/Until and Select Case value, range and relational clauses. For loops use `XPScriptRuntime.Range`; ForAll uses `LSForAllRuntime.Enumerate`; Select Case uses the existing `LSCoreCompare` helpers. Variant conditions use the existing generated `XPScriptNullRuntime.ConditionValue` helper. Indexed property assignments are still pending lowering.

`BoundMethodEmitter` wraps an already emitted body in a deterministic static C# method declaration and emits typed parameters with `ref` for ByRef symbols. It is the first integration boundary for a future declaration and compilation-unit emitter; it does not parse names, infer types or select runtime helpers.

The caller currently supplies declarations, runtime helpers, entry points and the surrounding C# compilation unit. This emitter is not connected to production compilation. Bound nodes now retain syntax spans, and `EmitWithSourceMap` produces `#line` directives plus generated-to-source mapping records. Target-specific generation and complete runtime integration remain open.

`tests/ast-emission` checks selected generated C# snapshots and compiles and executes generated code with Roslyn. It verifies boxed numeric types, string escaping, Null/Empty, widening and nested control flow. The probe runs in the existing language FullTest runner and the temporary AST branch workflow. This branch currently keeps FullTest jobs in `.github/workflows/fulltest.yml`; the four separate workflow files described in repository guidance are not present here.

`tests/ast-compile-probe` now drives an XPscript `Sub Main` through `DeclarationParser`, `StatementBinder` and `BoundMethodEmitter`, then compiles and invokes the generated C# with Roslyn. It is the first executable end-to-end AST compilation path and runs before the language FullTest.

The `xpscriptc ast-compile <file.xps> -o <directory>` command exposes that same experimental slice through the compiler CLI. It produces `Generated.dll`, which can be run with `dotnet`. The current slice requires `Sub Main()` and supports `Print` plus the earlier `Call AstPrint()` probe while the remaining runtime catalog and declaration lowering are migrated.

The legacy Optional bridge uses AST lexer spans to delimit nested supplied calls without rewriting strings or comments. The permanent CLI probe verifies recursive nesting and inner commas against AST output; the preserved main binary still has the flat-regex defect.

Print file-output preprocessing now uses lexer token boundaries; direct Print string literals containing commas or parentheses remain intact. The permanent AST CLI regression matches published main.

The AST path also invokes the shared reserved-identifier validator before binding. User names beginning with `__` are rejected with the same diagnostic contract as legacy compilation; the reserved-compiler-identifier regression covers CLI and MCP.

GoTo emits real bound control transfers and accepts labels only in the same Sub or Function. Labels are case-insensitive and can be reused in different procedures. In procedures containing GoTo, If/ElseIf/Else, While, Do and Select emit flat conditional branches with procedure-scope labels. The Language FullTest CLI probe exercises nested jumps, Function/Sub label scope and rejection of cross-procedure targets. For/ForAll transfers, local initialization across jumps and complete source-mapped target diagnostics remain open.

GoSub support was removed from the AST path by user decision on 2026-10-08. The binder explicitly rejects it with `GoSub is not implemented in the AST compiler. Use a Sub or Function instead.` Use `Call routine(...)` for a Sub, or a Function expression for a returned value. These routines have their own locals; pass required values as parameters. The published legacy compiler remains the compatibility baseline and still has GoSub syntax. `unsupported-gosub.xps` prevents silent no-op compilation. Production MCP still uses the legacy CompilerDriver, so this experimental diagnostic is not exposed there.

Scalar `Static` locals bind persistent storage instead of being rewritten to `Dim`. The compilation unit emits one private field per declaration, with a signature-derived identity separating procedures and overloads. Numeric/Boolean storage starts at zero/false and strings at empty. Initializer-free Static arrays, Lists, Variant, Object and user-class references also use persistent fields. `static-object.xps` verifies that Object storage starts as Nothing, `New Object()` creates an ExpandoObject, and subsequent calls retain the instance. Language FullTest runs this regression before the broader AST probes. Scalar explicit initializers are supported as an AST extension; complete initializer semantics remain migration work.

Declared Lists preserve list shape and element type, emit the existing `LSList<T>` runtime, and iterate its snapshot aliases. ForAll aliases bind in child scopes; emission maps reads/writes to the alias Value and ListTag to its Tag, restoring outer bindings after nested loops. List reference initializers and List parameters retain the element type. ByVal shares the List object; ByRef can also replace the reference. Functions can return a List via Variant, which can initialize a typed List. Function ByRef element/alias calls use named wrappers and the shared `LSListByRef<T>` capture: receiver, tag and value are evaluated once in argument order, and changed values are copied back in finally. Named wrappers can forward ordinary ref parameters without capturing them in a C# lambda. `list-functions.xps` and `list-function-order.xps` exercise these behaviors and exceptional copy-back. IsElement validates keyed access and checks Variant-supplied Lists through the shared interface.

AST supports explicit Sub calls with one or more matching typed ByRef List elements or ForAll aliases. The emitter evaluates each List and tag once, passes typed temporaries by reference, and copies them back in finally, including when the Sub throws. `list-byref-copyback.xps`, `list-byref-multiple-error.xps` and `forall-list-byref*.xps` cover numeric/string mutation, side-effecting tags, nested-loop scope and multiple arguments. Function expression calls remain migration work.

For `IsElement(declaredList(tag))`, emission calls ContainsTag on the List and evaluates the tag once, avoiding a read of a missing entry. `list-membership.xps` covers present/missing entries and a function-valued tag with a visible side effect in Language FullTest. Dynamically supplied Lists and complete argument validation remain pending; this is support for declared keyed List access.

`Erase declaredList(tag)` removes that tag, and `Erase declaredList` clears the List using the shared runtime. Neither operation reads an indexed value first. `list-erase.xps` verifies missing-tag safety, single/all removal and removal of current/future entries during snapshot iteration against published main and in Language FullTest. Array Erase and dynamically supplied Lists remain pending.

AST error-handling procedures now use a resumable instruction graph. `On Error Resume Next`, handler labels, disabling, retry, next-statement and label transfers execute through protected instructions. The ordinary statement emitter is reused for calls, ByRef copy-back, Static initialization and assignments. `Err` and `Error$` reuse the existing error runtime. Loop bodies retain their instruction continuation, so a handler outside a loop can resume inside it. Invalid handler/resume labels are source-mapped compiler diagnostics; Resume without an active handler raises a runtime error. The permanent fixtures are `resume-runtime.xps`, `resume-loops.xps` and `resume-handler-error.xps` in `tests/ast-compile-probe`.

XPImage expressions now emit calls to the existing image runtime. Native numeric/byte-array adaptations follow the runtime's public signatures, including overloads and case-insensitive names. Image procedure scopes clone ByVal parameters, recycle owned locals on every exit and preserve returned references (also through Variant); Static and borrowed ByRef references are not owned by the callee. CLI/MCP fixtures verify native construction/loading/editing and mapped invalid-member/constructor/read-only-property diagnostics.
